# Service catalog — what a business unit may claim

GENERATED by `tools/build_claim_schemas.py`. Do not edit by hand.

Every field below is one a claim manifest may set. Anything not listed is
owned by the platform and will be rejected by validation.

## `ack` — `claimSchema: ack/v1`

Module version pin: `1.0.0`

| Field | Type | Required | Allowed values | Description |
|---|---|---|---|---|
| `name` | string | yes | pattern `^[a-z][a-z0-9-]{2,30}$` | Cluster name. Lower-case letters, digits and hyphens, 3-31 characters, must start with a letter. |
| `size` | string | yes | `large`, `medium`, `small` | T-shirt size. The platform resolves it to a worker instance type and node count; a business unit never names an instance type directly. Changing what a size means is a sizing-map change and needs no manifest edits. |
| `namespaces` | array | no | — | Kubernetes namespaces to create on the cluster. Default `[]`. |

What `size` resolves to:

| Value | Resolves to |
|---|---|
| `large` | `{"worker_instance_type": "ecs.g6.2xlarge", "worker_count": 5}` |
| `medium` | `{"worker_instance_type": "ecs.g6.xlarge", "worker_count": 3}` |
| `small` | `{"worker_instance_type": "ecs.g6.large", "worker_count": 2}` |

## `oss` — `claimSchema: oss/v1`

Module version pin: `1.0.0`

| Field | Type | Required | Allowed values | Description |
|---|---|---|---|---|
| `name` | string | yes | pattern `^[a-z][a-z0-9-]{2,40}$` | Bucket name. Lower-case letters, digits and hyphens, 3-41 characters, must start with a letter. Must be globally unique across AliCloud. |
| `size` | string | yes | `archive`, `standard` | Storage tier. The platform resolves it to a concrete storage class; a business unit never names one directly. |
| `versioning` | boolean | no | — | Keep previous versions of overwritten or deleted objects. Default `false`. |
| `prefixes` | array | no | — | Key prefixes to create up front, for example "incoming/". These are also the only prefixes an access claim in the security lane may be scoped to. Default `[]`. |

What `size` resolves to:

| Value | Resolves to |
|---|---|
| `archive` | `{"storage_class": "Archive"}` |
| `standard` | `{"storage_class": "Standard"}` |

## `ram` — `claimSchema: ram/v1`

Module version pin: `1.0.0`

| Field | Type | Required | Allowed values | Description |
|---|---|---|---|---|
| `name` | string | yes | pattern `^[a-z][a-z0-9-]{2,40}$` | Logical name for the grant. Becomes the RAM role, group and policy name; a business unit never names those objects directly. |
| `identity_type` | string | yes | `workload`, `group` | Who the grant is for. "workload" binds a Kubernetes service account through RRSA; "group" binds a directory group of human users. |
| `level` | string | yes | `read`, `readwrite` | Access level. The platform resolves it to a concrete action list held in the access map. A business unit cannot enumerate API actions, which is what keeps privilege escalation out of a claim. |

What `level` resolves to:

| Value | Resolves to |
|---|---|
| `read` | `{"policy_actions": ["oss:GetObject", "oss:ListObjects"]}` |
| `readwrite` | `{"policy_actions": ["oss:GetObject", "oss:ListObjects", "oss:PutObject", "oss:DeleteObject"]}` |
